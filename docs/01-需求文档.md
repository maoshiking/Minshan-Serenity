# 需求文档

> 项目：岷山守静 —— 水磨羌道共生数字文化空间
> 性质：**非商业化**数字文化空间
> 本文档是全部工作的起点。功能取舍以本文档为准。

---

## 1. 一句话定义

一个以岷山与水磨羌道为地理底本、以道家"守静"为精神底色、由一只灵猫带领访客行走其间的数字文化空间。它不卖东西，也不追求留存时长。

---

## 2. 项目定位

### 2.1 是什么

| 维度 | 定位 |
|---|---|
| 性质 | 非商业化数字文化空间 |
| 地理底本 | 水磨古镇主街区及紧邻山体（核心区约 2×2 公里），基于真实 DEM 高程 |
| 精神底色 | 道家"守静"：克制、不喧哗、懂得不说话 |
| 核心角色 | 灵猫 —— 一只会看天说话、会闭嘴的导游 |
| 内容原则 | 宁可少讲，不可讲错；能看出处 |
| 技术外壳 | 三维空间 + 大模型对话 + 环境感知 |

### 2.2 不是什么

| 不是 | 说明 |
|---|---|
| 不是旅游推广页 | 无门票、无线路推荐导流、无商家 |
| 不是沙盒游戏 | 不做自由漫游、不做任务与奖励 |
| 不是聊天机器人套壳 | 灵猫的"活"来自环境感知与空间关系，不来自话术 |
| 不是文化科普大全 | 只讲有依据的，讲不清的坦白不讲 |
| 不是民族风情展演 | 不把仪式与信仰做成表演素材 |

## 3. 访客与场景

### 3.1 访客画像

| 类型 | 需求 | 设计响应 |
|---|---|---|
| 对羌族文化或地方史有兴趣的普通访客 | 想知道这是什么、为什么重要 | 资料卡 + 出处的可读呈现 |
| 文化研究者或学生 | 想核对出处 | 每条表述带 source 与信度 |
| 本地人与其后代 | 想看到自己的地方被认真对待 | 地名与事实的准确性优先于视觉华丽 |
| 对道家思想有兴趣者 | 想感受而非被说教 | 以场景与灵猫的行为渗透，不做标语式宣讲 |
| 无意深究的过路访客 | 想快速获得一个印象 | 首屏 30 秒内建立"这是能逛能聊的文化空间"的认知 |

### 3.2 核心场景

```
访客进入空间
   │
   ├─ 先看到地形与天气  →  明白这是一处真实的地方
   │
   ├─ 灵猫出现，安静待机  →  明白这里有一个"活物"
   │
   ├─ 点击一处点位  →  看到资料卡与出处  →  建立"这里说的话有依据"
   │
   ├─ 与灵猫对话  →  它能查天气、能看地图、能承认自己不确定
   │
   └─ 停留够久  →  灵猫主动开口一次，然后安静陪着  →  记住的是"它懂得不说话"
```

## 4. 智能体能力与验收标准

"超级智能体"是六个能力，不是一个功能。逐项给出可验收标准，避免"接入了大模型"这种无法验收的表述。

| 能力 | 可验收标准 | 阶段 |
|---|---|---|
| 多模态（识图） | 上传一张碉楼或羌绣照片，能识别物事类型并在地图上指出对应点位；识别不出时明确说识别不出 | P2 |
| 高质量 RAG | 每个文化回答都能给出处（哪份资料、哪一段），可展开；无资料时明确说"不确定"，**不得编造** | P2 |
| 大模型集成 | 流式输出，首包延迟可接受，断流可续传，上下文不失控 | P1 |
| 规划 | 给一个多步请求（如"带我看三处，路上的故事讲简略些"），能产出步骤并逐步执行；中途工具失败能换路子 | P2 |
| 工具调用 | 至少五个真实工具：查天气、查点位、检索文化库、算路线、读时间。调用参数与结果可回放审计 | P2（P1 只做天气与点位） |
| 自主决策 | 有明确触发条件与冷却窗口；能判断"不说话"；同一话题不重复；连续主动无回应后退化为静静陪伴 | P1 |

## 5. 分期范围

### P1 · 立骨：空间能站、猫能走、对话能通、环境能感知

| 做 | 验收 |
|---|---|
| 1. 地形渲染（真实 DEM 或占位资产，加载器元数据驱动） | 山形可辨，贴图与高程对齐 |
| 2. 坐标约定与数据加载管线 | 无第二套换算；点位贴地容差 ≤ 0.5 米 |
| 3. 定点停留 + 传送到访的交互形态 | 访客不会迷路，视角受控 |
| 4. 点位热区点击 → 资料卡（内容占位，带待核标记） | 卡片能看出出处与信度 |
| 5. 灵猫：程序化模型 + 六状态机 + 路点行走 + 尾耳姿态 | 30 秒内能看到行走与至少两次状态切换 |
| 6. 环境快照驱动光影、雾效与灵猫行为倾向 | 改天气能同时改变光与猫 |
| 7. 流式对话面板（SSE 全事件类型渲染，含过程态） | "正在查天气"可见；不出现长时间无反馈 |
| 8. 接口契约 + Mock 数据层 | 后端未就绪也能全流程跑通 |
| 9. 加载体验与降级 | 进度可见；8 秒兜底；WebGL 不可用不崩 |

### P2 · 通智：智能体六项能力落地

| 做 | 依赖 |
|---|---|
| 服务端 Agent（规划器、工具路由、记忆） | 后端 |
| RAG 检索与引用回链 | 文化表述卡（I3） |
| 识图 | 后端 + 豆包多模态 |
| 工具集扩到五件套 | 后端 |
| 会话记忆与摘要 | 后端 |

### P3 · 传神：活起来的体验与沉淀

| 做 |
|---|
| 主动交互的完整策略与冷却打磨 |
| 环境联动的光影深化（昼夜、节气、天气过渡） |
| 图鉴与长卷（把看过的点位与听过的故事攒起来） |
| 语音输入输出（Web Speech API） |
| 无障碍替代路径（纯文字长卷版） |
| 扩域到整条羌道（届时需上瓦片分级与 LOD） |

### 明确不做（P1/P2/P3 全程）

| 不做 | 理由 |
|---|---|
| 账号体系、登录、付费 | 非商业化定位下不必要 |
| 广告、导流、分享激励 | 直接违反定位 |
| 多人同游、实时协作 | 技术复杂度高，与"守静"气质不合 |
| 游戏化任务、积分、成就 | 会诱导停留时长，与项目目标相反 |
| 虚拟形象换装、皮肤 | 灵猫是角色不是商品 |
| 采集非必要个人信息 | 合规底线 |

## 6. 文化传播原则

### 6.1 三条原则

1. **准确优先于美观**。地名、年代、族属、习俗的表述错误，伤害远大于视觉朴素。
2. **有据可查**。每条文化表述带来源与信度；未审校内容显式标注"待核"。
3. **承认边界**。灵猫不知道的就说不知道。这不是缺陷，是可信度的来源。

### 6.2 "守静"如何表达

| 不做 | 改为 |
|---|---|
| 页面上写"道法自然"标语 | 用留白、慢节奏、低调光表达 |
| 灵猫说教式劝导 | 在合适的天气与时刻说一句、然后沉默 |
| 一直陪伴、一直搭话 | 主动三次无回应后，退化为安静陪伴 |
| 用道家符号装饰 | 不用符号，用行为 |

**核心判断**：**"懂得闭嘴"本身就是"守静"最直接的表达。**这一条应体现在主动交互冷却机制里（见 [frontend/01-导游灵猫-行为规格.md](frontend/01-导游灵猫-行为规格.md)）。

### 6.3 正能量

不是口号，是三条可执行的约束：不渲染悲情、不消费苦难、不猎奇。震后重建这类题材必须以事实与人的努力为叙述核心，不用灾难影像吸引注意力。

## 7. 非功能需求

| 类别 | 指标 |
|---|---|
| 首屏可交互 | 目标 ≤ 3 秒（地形单块加载） |
| 帧率 | 目标 60 fps；低端设备保底 30 fps |
| 内存 | 与所选 DEM 精度匹配；不做超出需要的精度 |
| 降级 | WebGL 不可用时切换为纯文字长卷替代路径，不崩 |
| 可访问性 | 对比度达标、键盘可操作、尊重减少动效偏好 |
| 响应式 | 桌面优先；窄屏可用（P1 不追求移动端体验最优） |
| 成本 | 会话轮数与 token 上限、工具结果复用、响应缓存 |
| 合规 | 不采集非必要个人信息；内容输出有兜底审核 |

## 8. 输入台账

| # | 输入项 | 需要什么形式 | 阻塞 | 责任人 |
|---|---|---|---|---|
| I1 | 地名与边界清单 | 表格或 GeoJSON：行政区归属、镇内核心地名正确写法、村寨名、四至边界 | 路线、点位、灵猫路径 | 你方 |
| I2 | DEM 资产 | 高程网格 + 元数据 + 严格对齐的纹理 + 来源与许可 | 地形渲染 | 你方 |
| I3 | 文化表述卡 | 每条：表述文本 / 来源 / 信度 / 标签 | P2 检索与问答 | 你方 + 文化顾问 |
| I4 | 后端对 SSE 事件类型的确认 | 确认契约第 7 节可行 | 契约冻结 | 你方后端 |
| I5 | 天气数据源（P1 不需要） | 数据源与许可 | P2 环境真实化 | 你方 |

## 9. 风险登记

| 风险 | 触发条件 | 影响 | 应对 |
|---|---|---|---|
| **文化误读** | 无审校内容进入产品 | **最高** | 只接受已审校表述卡；`verified` 字段做门槛；无资料时说不确定 |
| 重建街貌失真 | 把震后重建街貌表述为古建原貌 | 高 | 归入 I3，必须核 |
| 坐标管线返工 | 投影或世界坐标定错 | 高 | 契约第 2 节已冻结；加载器元数据驱动、不硬编码 |
| 资产迟到导致停摆 | I1/I2 晚到 | 中 | Mock 层 + 占位资产；加载器与数据分离 |
| 暗示商业化 | 出现购买入口或导流 | 中高 | 3.3 节约束；每次功能接入前过一遍 |
| 成本失控 | 多模态 + 多轮 Agent | 中 | token/轮数上限、工具结果复用、缓存 |
| 变成"骚扰机器人" | 主动交互无冷却 | 中 | 冷却机制 + 连续无回应退化 |
| 性能塌陷 | 真实地形 + 实时对话在低端设备 | 中 | 分级画质、能力探测降级、保底 30 fps |
| 文化顾问缺位 | 无人审校 | 中高 | 在顾问到位前，文化内容一律不进入产品 |

## 10. 验收单（P1）

| # | 验收项 | 判定 | 不可裁 |
|---|---|---|---|
| 1 | 打开页面，3 秒内出现可逛的地形 | 目视 | 是 |
| 2 | 山形与水系可辨认，贴图与高程不脱节 | 目视对照 | 是 |
| 3 | 点位标记贴地，不浮空不陷入 | 调试模式标记线 | 是 |
| 4 | 灵猫完成"待机 → 缓步 → 蹲坐 → 趋近"的连续表现，无硬切 | 录屏目视 | 是 |
| 5 | 改天气后，光影与灵猫行为同时改变 | 操作验证 | 是 |
| 6 | 对话过程出现"正在查天气"过程态，不出现无反馈空档 | 操作验证 | 是 |
| 7 | 后端不可用时自动切 Mock，页面不崩、有明确标注 | 断后端验证 | 是 |
| 8 | WebGL 不可用时显示替代路径，不白屏 | 禁用硬件加速验证 | 否 |
| 9 | 资料卡显示出处与信度标记 | 目视 | 是 |
| 10 | 键盘可完成点位切换与对话输入 | 拔鼠标验证 | 否 |
| 11 | 尊重减少动效偏好（`prefers-reduced-motion`） | 系统设置验证 | 否 |
| 12 | 无任何购买入口、导流、分享激励 | 全局检查 | 是 |
