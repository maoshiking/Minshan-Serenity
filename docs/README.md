## 三、三条贯穿全项目的约束

这三条不是建议，是硬约束。任何实现与小节冲突，以本节为准。

### 3.1 事实不得猜

- 未核实的地名、年代、文化表述，一律标注 `待核`，并且**不得写进代码里的真实数据**。
- 占位数据必须一眼可辨（例如名称含"占位"二字、`verified: false`）。
- 宁可少一个点位，不可多一句错话。

### 3.2 坐标只有一套

- 全链路唯一坐标系：`1 单位 = 1 米`，`+X 东`、`+Y 上`、`+Z 南`。
- 前端不得出现第二套换算；所有点位、路点、镜头、猫的路径共用同一套。
- 详见 [API_CONTRACT.md](API_CONTRACT.md) 第 2 节。

### 3.3 非商业化必须可验证

- 无购买入口、无导流、不诱导分享、不投放广告、不收集非必要个人信息。
- 任何后续功能接入，都要先过这一条。

## 四、当前阻塞项

| # | 阻塞项 | 阻塞什么 | 责任人 |
|---|---|---|---|
| I1 | 地名与边界清单 | 路线数据、点位数据、灵猫的行走路径 | 你方 |
| I2 | DEM 资产（高程 + 元数据 + 对齐纹理 + 许可） | 地形渲染 | 你方 |
| I3 | 文化表述卡 | P2 的知识问答与检索 | 你方 + 文化顾问 |
| I4 | 后端对 SSE 事件类型的可行性确认 | 契约冻结 | 你方后端 |

**I1 与 I2 不阻塞前端开发**：样式、动画骨架、访客模拟线路、地形加载器（元数据驱动）、流式对话解析、猫的状态机都可以用占位数据先做，真实资产到位后替换文件与 JSON，代码零改动。

## 五、术语

| 术语 | 含义 |
|---|---|
| 访客 | 使用者。本空间不用"用户"一词，避免产品化语气 |
| 灵猫 | 导游角色，抽象化猫形，非宠物猫、非吉祥物 |
| 点位 | 空间中的可交互位置，对应一件可讲的物事 |
| 资料卡 | 点击点位后展示的内容，含出处与信度标记 |
| 环境快照 | 一次下发的时间/天气/温度/能见度/节气数据，前端与灵猫共用 |
| 待核 | 未经你方或文化顾问确认的内容标记，前端会显式展示 |
