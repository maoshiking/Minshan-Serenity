# 数据与资产规范

> 本文档规定地形资产、坐标、点位与路线的数据形态。
> 接口字段以 [../API_CONTRACT.md](../API_CONTRACT.md) 为准，冲突时以契约文档为准。

---

## 1. 分工

| 环节 | 责任方 | 产出 |
|---|---|---|
| 高程数据获取、投影、切片 | 你方 | 高程网格文件 |
| 影像纹理获取与配准 | 你方 | 与高程严格对齐的纹理 |
| 元数据生成 | 你方 | 元数据 JSON |
| 加载与渲染 | 我方 | 地形加载器、渲染、贴地、镜头 |
| 点位与路线内容 | 你方（基于地名清单） | `spots` / `routes` 数据 |
| 点位与路线的占位数据 | 我方 | 一眼可辨的占位数据 |

**E1 分工的含义**：地理数据处理留在你方。但**不代表前端可以硬编码坐标**——加载器必须完全由元数据驱动，否则真实资产到位时仍要改代码。

## 2. 地形资产规格

### 2.1 高程网格

| 项 | 规定 |
|---|---|
| 格式 | PNG，16 位高程打包进 RGBA 通道 |
| 网格 | 规则网格，`row-major` |
| 建议分辨率 | 核心区 2×2 公里下建议 257×257 或更高；由实际 DEM 精度决定 |
| 文件路径 | `/assets/terrain/<id>-height.png` |
| 编码 | `rgba16-uint16`（P1 固定，不支持其它编码） |

### 2.2 元数据（模板）

```json
{
  "id": "shuimo-core",
  "origin": { "lon": 0.0, "lat": 0.0, "corner": "northwest" },
  "sizeMeters": { "width": 2000, "height": 2000 },
  "grid": { "cols": 257, "rows": 257, "layout": "row-major" },
  "elevation": { "min": 0.0, "max": 0.0, "unit": "m", "relativeTo": "origin" },
  "heightScale": 1.0,
  "encoding": "rgba16-uint16",
  "files": {
    "height": "/assets/terrain/shuimo-core-height.png",
    "texture": "/assets/terrain/shuimo-core-texture.webp"
  },
  "meta": {
    "source": "",
    "license": "",
    "resolutionMeters": 12.5,
    "producedBy": "",
    "producedAt": ""
  }
}
```

**注意 `origin.corner` 字段**：必须注明 `origin` 是哪个角。契约原文只说"网格左上角或中心须注明"，这里补一个显式字段，避免歧义。若你方已有固定约定，请告知，我按你方的来。

### 2.3 纹理

| 项 | 规定 |
|---|---|
| 格式 | WebP 优先，JPG 兜底 |
| 分辨率 | 2K 起步，核心区建议 4K |
| 对齐 | **必须与高程严格对齐**。错位会导致"路跑到山脊上" |
| 色彩 | 不做风格化处理（风格由渲染侧的光照与后处理承担） |

## 3. 坐标约定（冻结）

```
L1 地理坐标   WGS84 (lon, lat)        —— 仅出现在数据生产侧
      │ 以核心区中心为原点的局部切平面投影
      ▼
L2 局部米制   (x 东向米, y 相对高, z 南向米)
      │ P1 阶段原点重合，1 单位 = 1 米
      ▼
L3 世界坐标   Three.js，+X 东 / +Y 上 / +Z 南
```

| 规定 | 内容 |
|---|---|
| 单位 | `1 three 单位 = 1 米` |
| 纵向尺度 | 数据一律真实米值；视觉放缩若需要，只在渲染侧施加，**不写入数据** |
| 前端换算 | **禁止**出现第二处经纬度换算 |
| 权威来源 | 点位、路点一律使用 world 坐标 |

**这一节是全部空间数据的地基。改动此节等同于重做地形、点位、路径与镜头。**

## 4. 点位数据规格

| 字段 | 规定 |
|---|---|
| `id` | 稳定、不含中文、不含真实地名拼音（避免改名后失效） |
| `name` | 显示名。**未核销时必须是明显的占位名** |
| `coord` | world 坐标，`y` 与地形高度容差 ≤ 0.5 米 |
| `hotspotRadius` | 建议 8–15 米；过小难以点中，过大互相重叠 |
| `type` | `architecture` / `landscape` / `craft` / `custom` / `folklore`（P1 冻结） |
| `verified` | 地名与文化内容是否已审校。`false` 时前端显示"待核"，且不参与知识问答 |
| `card.paragraphs[].source` | 来源。未核销时写"待核" |
| `card.paragraphs[].confidence` | `verified` / `pending` |

### 4.1 命名规约

**未核销的占位点位命名必须一眼可辨**，例如 `占位点位 · 建筑类 01`。禁止使用任何形近真实地名的编造名称——那会让人误以为已经核过。

## 5. 路线数据规格

| 字段 | 规定 |
|---|---|
| `waypoints` | world 坐标序列；须避开山体岩面，不得穿模 |
| `stops` | 关联 `spotId` 与 `dwellSeconds`（建议 30–90 秒） |
| `durationMinutes` | 仅供展示，不作为逻辑依据 |
| `difficulty` | `easy` / `normal` / `hard`，影响灵猫速度与台词倾向 |

**路点与地形的两处校验**：

1. 每个路点吸附地形后，相邻路点的连线不得穿过高于两端点的地形（否则会出现"穿过山脊"的视觉错误）。
2. 相邻路点间距建议 3–10 米，过密浪费性能，过疏导致贴地跳变。

## 6. 从占位到真实：交接规程

这是本规范最实用的一节。占位与真实资产**必须走同一条加载路径**，否则"替换即可"是假的。

| 步骤 | 操作 | 验证 |
|---|---|---|
| 1 | 保持代码不变，只替换元数据 JSON 的 `files` 路径 | 页面能加载新地形 |
| 2 | 替换高程与纹理文件 | 山形改变，贴图对齐 |
| 3 | 用地图/实测点抽查 3–5 处高程 | 与元数据 `elevation` 区间一致 |
| 4 | 重新生成点位与路线的 world 坐标 | 点位贴地、路点不穿模 |
| 5 | 逐项核销 `待核` 标记 | 全部核销或明确保留待核 |

**若某一步需要改代码，说明加载器设计有缺陷，应回头修加载器，而不是在数据侧做适配。**

## 7. 许可与核销清单

上线前逐项核销。任一未核销项，对应功能不得上线。

| # | 项 | 需确认内容 | 状态 |
|---|---|---|---|
| L1 | DEM 数据源 | 名称、精度、许可是否允许公开使用 | 待核 |
| L2 | 影像纹理 | 来源与许可 | 待核 |
| L3 | 文献/志书 | 是否允许网络公开引用、可否展示原文片段 | 待核 |
| L4 | 老照片与民俗照片 | 版权与肖像权 | 待核 |
| L5 | 字体 | 中文字体的授权与自托管许可 | 待核 |
| L6 | 天气数据源（P2） | 来源、频率限制、商用许可 | 待核 |

### 7.1 字体授权提示

方向 B「山志」需要中文衬线与等宽字体。**中文字体授权是常见踩坑点**：

| 字体 | 授权状况 | 可否自托管 |
|---|---|---|
| 思源宋体 / 思源黑体（Source Han） | SIL OFL | 可，需保留许可声明 |
| Noto Serif SC / Sans SC | SIL OFL | 可，需保留许可声明 |
| JetBrains Mono | SIL OFL | 可 |
| 系统字体（宋体/黑体等） | 随系统，不可分发字体文件 | 不可自托管，只能引用字体名 |

**字号子集化是必须的**：中文全字库动辄数 MB，必须按实际用字子集化后再打包，否则首屏体积失控。
